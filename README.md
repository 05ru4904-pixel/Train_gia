# Тренажёр ЕГЭ — Telegram-бот + Mini App

Подготовка к ЕГЭ по русскому языку: тренировка по номерам заданий, полные варианты
с таймером, статистика, отдельный админ-бот для наполнения базы. Техническое
задание — [TZ.md](TZ.md), грабли прошлых проектов — [problems.md](problems.md).

## Структура

```
main.py            точка входа: БД + FastAPI + оба бота в одном процессе
admin.py           отдельная точка входа для админ-бота (если вынести в свой сервис)
config.py          настройки из переменных окружения

core/               чистая логика без БД и сети
  tasks_meta.py       темы заданий №1-26
  scoring.py          проверка ответов, баллы, регламент (лимит времени и т.п.)
  parser.py           разбор текстовых шаблонов админ-бота

db/
  models.py           модели SQLAlchemy
  database.py         подключение, пул, миграции
  crud.py             вся работа с БД

api/
  main.py             FastAPI-приложение, отдача Mini App
  auth.py             проверка подписи initData Telegram
  serializers.py      сборка JSON-ответов
  routers/            /api/state, /api/training/*, /api/variant/*, /api/stats

bots/
  user_bot.py         основной бот — открывает Mini App
  admin_bot.py        админ-бот — управление базой заданий

static/               Mini App: index.html, app.js, app.css, локальные шрифты
scripts/
  import_variant.py   импорт варианта из JSON — основной способ наполнения базы
  seed.py             демо-задания для проверки интерфейса
tests/                 тесты (запускаются напрямую, без pytest)
```

## Запуск локально

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt
copy .env.example .env            # заполнить токены и DATABASE_URL
python scripts\seed.py --per 15   # демо-задания, чтобы было что тренировать
python main.py
```

Без `DATABASE_URL`, указывающего на Postgres, `main.py` не поднимется — база
обязательна. Без `BOT_TOKEN`/`ADMIN_BOT_TOKEN` соответствующий бот просто не
запустится (в лог уйдёт предупреждение), но HTTP-сервер и Mini App продолжат
работать — этого достаточно, чтобы открыть `/app` в браузере и посмотреть вёрстку.

## Тесты

Без pytest, каждый файл — самостоятельный скрипт с понятным выводом:

```bash
python tests/test_parser.py       # шаблоны админ-бота (27 сценариев)
python tests/test_scoring.py      # проверка ответов и баллы (15 сценариев)
python tests/test_auth.py         # подпись initData (9 сценариев)
python tests/test_admin_cards.py  # карточка задания в админ-боте (8 сценариев)
python tests/test_api.py          # сквозной сценарий на SQLite (13 сценариев)
```

`test_api.py` поднимает всё приложение в памяти (httpx + ASGI, без реального
сервера) на временной SQLite-базе и проходит тренировку, полный вариант, паузу
таймера, статистику и фильтр по датам целиком — это самый полезный тест при
любых будущих изменениях API.

## Деплой на Railway

1. Добавить плагин Postgres, скопировать его `DATABASE_URL` (реальное значение,
   не `${{Postgres.DATABASE_URL}}`) в переменные сервиса приложения.
2. Деплой по `Dockerfile` (не nixpacks).
3. После первого деплоя — вписать `WEBAPP_URL` (публичный домен + `/app`).
4. Залить задания: `python scripts/import_variant.py Задания/1 --variant 1`
   (см. раздел ниже) либо поштучно через админ-бота (`/add`, `/batch`).

Подробности и типичные ошибки — в [problems.md](problems.md).

## Наполнение базы

Основной путь — сырой вариант с сайта-источника, скопированный как есть.

Через админ-бота (обычный путь): `/upload` → прислать файлом `.txt` в UTF-8. Бот
разбирает его, присылает полный разбор отдельным файлом на проверку и заливает
только после подтверждения кнопкой.

Через терминал (когда нужен контроль над JSON):

```bash
python scripts/parse_raw.py Задания/1 --report            # сырой текст -> Задания/1.json
python scripts/import_variant.py Задания/1.json --dry-run # только проверить
python scripts/import_variant.py Задания/1.json --variant 1
python scripts/import_variant.py Задания/                 # всю папку разом
```

Разбор живёт в [core/raw_variant.py](core/raw_variant.py) и подчиняется одному
правилу: **при любой неоднозначности задание не собирается**, а попадает в
`problems`, и тогда не заливается вообще ничего. Прошлый парсер разбирал текст
эвристиками, на задании №13 молча потерял вариант ответа и сдвинул правильные
ответы на соседние — такие ошибки не видны в логах и попадают прямо к ученику.
Вид задания берётся из таблицы `KIND_BY_NUMBER` по номеру, а не угадывается по
вёрстке. Дальше JSON проверяется ещё раз структурно, уже перед базой.

ID источника не сохраняется, у каждого задания свой. Повторная заливка того же
файла ничего не задвоит: задание опознаётся по содержимому.

### Виды заданий

| Вид | Как отвечают | Как проверяется |
|---|---|---|
| `choice` | выбор из пронумерованных вариантов | множество выбранных номеров |
| `open` | вписывают слово | сверка с любой из допустимых форм, без учёта регистра, пробелов и ё/е |
| `digits` | вписывают цифры | набор цифр, порядок не важен — как на бланке |
| `match` | А-Д сопоставляют с 1-9 | точная последовательность |

Сузить набор видов, попадающих в тренировки, можно через `RENDERABLE_KINDS` в
`core/tasks_meta.py` — пригодится, если какой-то экран временно сломан.

Админ-бот работает со всеми четырьмя видами: `/templates` показывает шаблон
каждого, вид определяется по форме сообщения (есть варианты «А)» — выбор; есть
ещё и «1)» с ответом «А-3, Б-1» — соответствие; вариантов нет — вписывание).
Кнопка «Редактировать» отдаёт задание готовым шаблоном: поправить строку и
прислать обратно — так правится любое поле, включая ответ и материал.

## Известные упрощения первого этапа

- **Тестовый балл** — линейное приближение (`raw / max * 100`), пока не заполнена
  официальная таблица перевода в `core/scoring.py::RAW_TO_TEST_SCORE`. Приложение
  честно показывает пометку об этом на экране результата варианта.
- **Задания на соответствие** засчитываются по принципу «всё или ничего», хотя в
  реальном ЕГЭ балл даётся за каждое верное соответствие. Единственное место для
  доработки — `core/scoring.py::award_points`.
- **Темы заданий** в `core/tasks_meta.py` взяты из макета и расходятся с
  нумерацией источника как минимум по №22 и №26. Требуют сверки со
  спецификацией, которую считаем эталонной.
- Задание №27 (сочинение) не реализовано — по ТЗ.
