# Тренажёр ЕГЭ — Telegram-бот + Mini App

Подготовка к ЕГЭ по русскому языку: тренировка по номерам заданий, полные варианты
с таймером, статистика, отдельный админ-бот для наполнения базы. Техническое
задание — [TZ.md](TZ.md), грабли прошлых проектов — [problems.md](problems.md).

## Структура

```
main.py            точка входа: БД + FastAPI + оба бота в одном процессе
admin.py           отдельная точка входа для админ-бота (если вынести в свой сервис)
config.py          настройки из переменных окружения

core/               чистая логика без БД и сети
  tasks_meta.py       темы заданий №1-26
  scoring.py          проверка ответов, баллы, регламент (лимит времени и т.п.)
  parser.py           разбор текстовых шаблонов админ-бота

db/
  models.py           модели SQLAlchemy
  database.py         подключение, пул, миграции
  crud.py             вся работа с БД

api/
  main.py             FastAPI-приложение, отдача Mini App
  auth.py             проверка подписи initData Telegram
  serializers.py      сборка JSON-ответов
  routers/            /api/state, /api/training/*, /api/variant/*, /api/stats

bots/
  user_bot.py         основной бот — открывает Mini App
  admin_bot.py        админ-бот — управление базой заданий

static/               Mini App: index.html, app.js, app.css, локальные шрифты
scripts/seed.py        демо-задания для проверки интерфейса
tests/                 тесты (запускаются напрямую, без pytest)
```

## Запуск локально

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt
copy .env.example .env            # заполнить токены и DATABASE_URL
python scripts\seed.py --per 15   # демо-задания, чтобы было что тренировать
python main.py
```

Без `DATABASE_URL`, указывающего на Postgres, `main.py` не поднимется — база
обязательна. Без `BOT_TOKEN`/`ADMIN_BOT_TOKEN` соответствующий бот просто не
запустится (в лог уйдёт предупреждение), но HTTP-сервер и Mini App продолжат
работать — этого достаточно, чтобы открыть `/app` в браузере и посмотреть вёрстку.

## Тесты

Без pytest, каждый файл — самостоятельный скрипт с понятным выводом:

```bash
python tests/test_parser.py    # шаблоны админ-бота (16 сценариев)
python tests/test_scoring.py   # баллы и регламент (10 сценариев)
python tests/test_auth.py      # подпись initData (9 сценариев)
python tests/test_api.py       # сквозной сценарий на SQLite (10 сценариев)
```

`test_api.py` поднимает всё приложение в памяти (httpx + ASGI, без реального
сервера) на временной SQLite-базе и проходит тренировку, полный вариант, паузу
таймера, статистику и фильтр по датам целиком — это самый полезный тест при
любых будущих изменениях API.

## Переменные окружения

См. [.env.example](.env.example) — там же объяснение к каждой (публичный
DATABASE_URL, обязательный https в WEBAPP_URL и т.д., со ссылками на разделы
playbook).

## Деплой на Railway

1. Добавить плагин Postgres, скопировать его `DATABASE_URL` (реальное значение,
   не `${{Postgres.DATABASE_URL}}`) в переменные сервиса приложения.
2. Деплой по `Dockerfile` (не nixpacks).
3. После первого деплоя — вписать `WEBAPP_URL` (публичный домен + `/app`).
4. Залить задания через админ-бота (`/add`, `/batch`, `/variant`) либо для
   проверки — `python scripts/seed.py`.

Подробности и типичные ошибки — в [problems.md](problems.md).

## Известные упрощения первого этапа

- **Тестовый балл** — линейное приближение (`raw / max * 100`), пока не заполнена
  официальная таблица перевода в `core/scoring.py::RAW_TO_TEST_SCORE`. Приложение
  честно показывает пометку об этом на экране результата варианта.
- **Задания №8 и №26** засчитываются по принципу «всё или ничего», хотя в реальном
  ЕГЭ у них частичный балл за каждое верное соответствие. Единственное место для
  доработки — `core/scoring.py::award_points`.
- Задание №27 (сочинение) не реализовано — по ТЗ.
